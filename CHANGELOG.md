# Unreleased

* protoc-gen-c: Support `edition = "2023"` .proto files. The `field_presence` and `repeated_field_encoding` features select the same generated code and wire behavior as proto2/proto3 (explicit vs. implicit presence, packed vs. expanded). Requires protoc 27 or later. Generated descriptors now record the resolved features: new `ProtobufCFeatures` (with `field_presence`, `enum_type`, `repeated_field_encoding`, `utf8_validation`, `message_encoding`, `json_format`) and a `features` member in message, field and enum descriptors, taking over a previously reserved slot (NULL in code generated by older versions; no ABI change).
* **Behavior change:** `protobuf_c_message_unpack()` now honors closed enums (`features.enum_type = CLOSED`, which is what proto2 enums are). A value that a closed enum does not define is no longer stored in the field: it is kept as an unknown field (and written back by pack), the field keeps its default value, a required field set to such a value counts as missing, and in a packed repeated field only the undefined elements move to the unknown fields. This matches the C++ implementation. Open enums (proto3, edition 2023 by default) and code generated by older versions of protoc-gen-c (no features recorded) accept any value as before. Regenerate proto2 code to get the new behavior; to keep the old behavior for an enum in an edition file, leave it open.
* **Behavior change:** `protobuf_c_message_unpack()` now fails if a `string` field whose `utf8_validation` feature is `VERIFY` (the default for proto3 files and `edition = "2023"` files; not proto2, and not code generated by older versions) holds invalid UTF-8, as the C++ implementation has done for proto3 since 3.0.0-beta-1. The check calls the new global function pointer `protobuf_c_validate_utf8`, initially `protobuf_c_validate_utf8_strict`. New `protobuf_c_message_validate_utf8()` checks a message tree the same way before it is packed, since packing cannot fail and does not look at strings. Programs that must keep accepting anything, as earlier versions did, can set it to their own function, e.g. one that warns and returns true (see the example in `protobuf-c.h`); edition 2023 files can also opt out per field or file with `features.utf8_validation = NONE`.
